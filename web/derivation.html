THE MATHEMATICS / EXPLAINED STEP BY STEP

From a cost
to a curve.

What we want to minimize. The equations that follow.
And how a computer actually solves them.

Start with the words; the equations make each step precise. No Python runtime is needed to read this page.

Which equations does the playground solve today?

It still uses the original energy: cost × squared speed. The intended path-planning objective is cost × distance. Those are different problems. This page derives both and explains the correction; it does not switch the playground to the corrected formulation.

The numerical implementation has been modernized, but the original continuous equations are preserved.

01 / SET UP THE PROBLEM

A route between two fixed points.

We want a curve in a two-dimensional plane. Its start and destination are fixed. Between them, we can bend the curve to pass through regions with different costs.

q(t) = (x(t), y(t)), for t from 0 to 1.

The parameter t labels positions along the curve. It is not necessarily physical time. Traversing the same route with a different schedule changes the function q(t), but not its geometric shape.

q
The position on the path: an x coordinate and a y coordinate.
q′ and q″
First and second derivatives with respect to t: parameter velocity and acceleration.
‖q′‖
Speed along the curve: the square root of x′² + y′².
c(q)
A positive spatial cost field. High values make a region more expensive.
∇c
The gradient: the vector (cₓ, cᵧ) pointing toward the fastest increase in cost.
cₓ and cᵧ
Partial derivatives of c with respect to x and y. A dot between vectors means their dot product.

Throughout, we assume a smooth, strictly positive cost field. The Gaussian field used here satisfies that assumption. For the length derivation, we also assume a regular curve: its speed is nonzero. A constant path between identical endpoints can be handled separately.

02 / THE INTENDED OBJECTIVE

Pay for the distance you travel.

A small displacement along the curve has length ds = ‖q′‖ dt. Multiply that distance by the local cost and add it up along the route:

J = the integral of cost times distance along the path.

This is the objective we actually want for weighted-distance path planning. If a region has cost 9, each unit of distance through it costs nine times as much as a unit through a region with cost 1.

Changing the traversal schedule does not change J. Moving twice as fast for half as long covers the same distance and incurs the same cost.

Soft costs, not solid walls.

An obstacle raises c. It does not make a region forbidden. Even a minimizing route may cross an expensive region if the alternative detour costs more.

03 / START WITH WEIGHTED LENGTH

Why the square root is awkward.

The integrand is called the Lagrangian. Write v for q′ and u for its magnitude, so L = c(q)u. The Euler–Lagrange equation is the condition that a small change to the curve has zero first-order effect on the objective:

The derivative along the path of ∂L/∂v, minus ∂L/∂q, equals zero.

Differentiate speed with respect to velocity: the derivative of ‖v‖ is v/‖v‖. Holding velocity fixed, differentiating with respect to position gives the gradient of c times speed. Therefore:

∂L/∂v = cv/u, and ∂L/∂q = u∇c.
The weighted-length Euler–Lagrange equation is d(cv/u)/dt − u∇c = 0.

To see what prevents this from immediately giving an ordinary acceleration equation, expand the derivative. Along the path, c′ = ∇c · v, while u′ = (v · q″)/u:

Expanding the derivative produces terms involving acceleration both directly and projected along the velocity.

Let T = v/u be the unit tangent, and let I be the identity matrix. The matrix I − TTᵀ removes the component of a vector along the path. Rearranging gives:

Only the component of acceleration perpendicular to the path is determined.

This equation determines the bending of the path but leaves acceleration along the path unspecified. That is expected: the objective does not care about the traversal schedule. The velocity Hessian, (c/u)(I − TTᵀ), is singular in the tangent direction.

We could solve the length equations with a separate parameterization condition. A compatible energy formulation supplies that condition naturally and avoids dividing by speed.

04 / THE SQUARING QUESTION

A valid shortcut needs one extra argument.

Because J is nonnegative, J and J² have the same minimizers. But squaring the entire integral is not the same operation as squaring the integrand:

The square of an integral does not generally equal the integral of the square.

For example, take f = 0 on the first half of the interval and f = 2 on the second half. The square of its integral is 1, while the integral of its square is 2.

Here there is a geometric way to justify a squared integrand. Define the corrected energy by squaring the whole local expression, including the cost:

Corrected energy = the integral of cost squared times speed squared.

The Cauchy–Schwarz inequality on an interval of length one says:

Weighted distance squared is at most the corrected energy.

Equality holds exactly when weighted speed c(q)‖q′‖ is constant. This means moving more slowly, in parameter t, through more expensive regions. Ordinary speed need not be constant.

For any regular geometric route, we can choose that traversal schedule without changing the route. An explicit new parameter is the fraction of total weighted distance already traveled:

The new parameter is accumulated weighted distance divided by total weighted distance.

In this parameter, c‖dq/dτ‖ = J everywhere. So the lowest corrected energy available for any fixed route is exactly its weighted distance squared. Minimizing corrected energy over curves and their parameterizations therefore gives the same minimizing geometric routes as minimizing J.

This is the usual length–energy relationship for the metric c²I. It is a continuous result; a finite grid approximates it. It is not a claim that the two objectives agree for an arbitrary fixed parameterization.

05 / DERIVE THE ENERGY EQUATIONS

One derivation covers both versions.

Introduce a positive coefficient A(q), and temporarily leave its meaning open:

Use a general coefficient A multiplying squared speed.

At the end we will choose A = c for the current implementation, or A = c² for the corrected objective.

First: why Euler–Lagrange applies.

Perturb the curve by a small amount εη(t), keeping both endpoints fixed, so η(0) = η(1) = 0. Differentiate the energy with respect to ε at zero:

The first variation has a change-in-position term and a change-in-velocity term.

Integrate the second term by parts. Its endpoint contribution vanishes because η is zero at both ends:

After integration by parts, all the dependence on the perturbation is through η.

For this to vanish for every interior perturbation η, the vector in brackets must be zero. That is the Euler–Lagrange condition. It is necessary for a smooth minimizer, but it is also satisfied by other stationary curves.

Next: expand the x equation.

The x derivatives of the Lagrangian are Aₓ times squared speed, and 2Ax′.

A changes as the curve moves, so the chain rule gives dA/dt = Aₓx′ + Aᵧy′. Apply the product rule to 2Ax′:

The total derivative is 2Ax″ + 2(Aₓx′ + Aᵧy′)x′.

Subtract ∂L/∂x and set the result to zero:

Collect the terms in the x Euler–Lagrange equation.

Collect like terms and solve for x″:

x″ = [Aₓ(y′² − x′²) − 2Aᵧx′y′] / (2A).

Repeat for y.

The y equation follows from ∂L/∂y′ = 2Ay′ and ∂L/∂y = Aᵧ(x′² + y′²).
y″ = [Aᵧ(x′² − y′²) − 2Aₓx′y′] / (2A).

These are coupled, second-order ordinary differential equations: each coordinate's acceleration depends on both coordinates and both velocities. In compact vector form:

The vector ODE combines the x and y equations.

An energy-stationary curve also has A‖q′‖² constant along it. Substituting the ODE into its derivative makes the terms cancel. Thus the energy equations select a traversal schedule as well as a shape.

06 / SUBSTITUTE THE COST

The missing square changes the ODE.

Current implementation: A = c.

Substitution immediately gives the original equations, which the playground still solves:

The current x and y ODEs have denominator 2c.

The geometric length associated with this energy uses √c as its distance weight. The energy chooses constant √c‖q′‖. With cost 9, this amounts to a geometric distance weight of 3.

Corrected weighted-distance formulation: A = c².

Now Aₓ = 2ccₓ and Aᵧ = 2ccᵧ. Substitute those into the general equations and cancel the common factors:

The corrected x and y ODEs have denominator c, rather than 2c.

The right-hand side is twice the current one when evaluated at the same position and velocity. This formulation selects constant c‖q′‖ and has the intended minimizing geometric routes.

Keep these three functionals distinct
Formulation Local integrand Geometric meaning
Intended weighted distance c × speed Accumulates c per unit distance; any traversal schedule.
Current energy c × speed² Corresponds to distance weighted by √c, with a selected schedule.
Corrected energy c² × speed² Corresponds to distance weighted by c, with a selected schedule.

Here c² means the square of the entire field, including its baseline and overlapping bumps. Squaring individual obstacle weights would not make this correction. Switching the project would also require updating the Jacobian, energy diagnostic, tests, and presentation.

07 / THE OBSTACLE LANDSCAPE

The derivatives are explicit.

Each obstacle has centre oᵢ, nonnegative strength wᵢ, and positive width σᵢ. Width is the distance at which its bump falls to 1/e of its peak. In the API it is called width.

The cost is one plus the sum of Gaussian obstacle bumps.

Let dᵢ = q − oᵢ. Differentiating the exponential gives the gradient:

The cost gradient is the sum of each bump times −2dᵢ/σᵢ².

Differentiate once more to get the Hessian H: the matrix of second spatial derivatives. This is needed for the Newton Jacobian.

The Hessian sums a displacement outer-product term and an identity-matrix term for each bump.

The implementation evaluates these formulas directly with NumPy. It does not invoke a symbolic algebra engine while the user drags an obstacle. For the corrected energy, the corresponding coefficient derivatives would be:

The gradient and Hessian of the squared field follow from the product rule.

08 / WHAT KIND OF ODE PROBLEM?

We know both ends, not the starting velocity.

The start a and destination b are prescribed boundary conditions.

That makes this a boundary-value problem. Ordinary forward integration would require an initial velocity and might miss the destination. Instead, this solver guesses the whole path and adjusts its interior points together while keeping the endpoints fixed.

With N interior points, there are 2N unknown scalar coordinates. The ODE supplies two equations at each interior point, also 2N equations.

The three initial guesses use the same parameter samples but different polynomial shapes:

Interpolate the x and y endpoint coordinates using powers of t.

Straight: p = r = 1. Bend x: p = 5, r = 1. Bend y: p = 1, r = 5. These can explore different stationary solutions. If an endpoint coordinate does not change, some guesses differ only in traversal schedule.

Two different meanings of “step.”

The spacing between path samples is a step in the parameter t. A Newton iteration updates the entire guessed curve. The animation shows Newton iterations, not a robot advancing through time. Euler–Lagrange is also unrelated to using the forward Euler integration method.

09 / FINITE DIFFERENCES

Replace derivatives with neighbouring points.

Store N interior points plus the two endpoints. That makes N + 2 points and N + 1 intervals:

The uniform spacing is h = 1/(N + 1).

With the default N = 30, the path contains 32 points, separated by 1/31 in t. With three interior points, the five sample parameters would be 0, ¼, ½, ¾, and 1.

The Taylor expansions of the two neighbours are:

Taylor expansion expresses each neighbour in terms of derivatives at the middle point.

Subtract the expansions to estimate velocity. Add them, then subtract twice the middle point, to estimate acceleration:

Central differences approximate velocity and acceleration from three adjacent points.

Both estimates have error of order h² for a sufficiently smooth curve. The second derivative needs h² in the denominator. The old implementation used h in its residual while its Jacobian used h²; the modernization corrected this and made h agree with the actual point spacing.

At each interior point, subtract the acceleration predicted by the ODE from the finite-difference acceleration. This difference is the residual:

Rᵢ measures how far the three-point estimate is from satisfying the ODE.

A solution has every residual equal to zero. Near the first and last interior points, the neighbouring endpoint enters this calculation as a known constant.

10 / SOLVE THE NONLINEAR SYSTEM

Ask which move should reduce the error.

Stack the interior coordinates into one vector z = (x₁, y₁, x₂, y₂, …). Stack the two-coordinate residuals in the same order. The task is now R(z) = 0.

The Jacobian JR is the matrix describing how each residual changes when each coordinate changes. This JR is a matrix, distinct from the weighted-distance functional J earlier.

Linearize the residual near the current guessed path.

Make this approximation equal to zero, and solve for the proposed coordinate change Δ:

Solve one linear system, then add the proposed change scaled by α.

Undamped Newton takes the full step, α = 1. Damped Newton may shorten it. The code uses np.linalg.solve; computing a matrix inverse is unnecessary. Because F depends on position and velocity, the residual and Jacobian are recalculated at every iteration.

  1. 01Evaluate the current residual
  2. 02Build the Jacobian
  3. 03Solve for the proposed move
  4. 04Choose a step length
  5. 05Update interior points
  6. 06Measure the new residual

11 / DIFFERENTIATE THE RESIDUAL

Each point only talks to its neighbours.

A residual Rᵢ depends only on qᵢ₋₁, qᵢ, and qᵢ₊₁. Its Jacobian therefore has three potentially nonzero 2 × 2 blocks per interior-point row. Define Fq as the derivative of F with respect to position, holding velocity fixed, and Fv as the derivative with respect to velocity, holding position fixed.

The left, middle, and right Jacobian blocks follow by differentiating the three-point residual.

The signs of the velocity terms come from vᵢ = (qᵢ₊₁ − qᵢ₋₁)/(2h). Moving the left neighbour changes vᵢ with a minus sign; moving the right neighbour changes it with a plus sign. The residual subtracts F, introducing another minus sign.

Blocks corresponding to fixed endpoints are omitted from the unknown matrix. The implementation stores this structured matrix densely, which is practical for the small browser problems.

The analytic formulas for Fq and Fv

For the general energy coefficient A, write g = ∇A and HA = ∇²A. Differentiating F by the product and quotient rules gives:

The position derivative contains the Hessian of A and a quotient-rule correction.
The velocity derivative contains two outer products and a scalar multiple of the identity.

A product such as vgᵀ is an outer product: its entry in row j and column k is vⱼgₖ. In the current code, A = c, so g and HA are exactly the Gaussian-field gradient and Hessian from section 7.

The position derivative's final term comes from differentiating 1/A. In the velocity derivative, differentiate ‖v‖² to get 2v, and differentiate v(g · v) using the product rule.

For the corrected coefficient A = c², these derivatives simplify to twice the current Fq and Fv. The finite-difference terms I/h² and −2I/h² do not double.

12 / KEEP NEWTON UNDER CONTROL

A full step is only a local prediction.

The linear approximation may be poor far from the current guess. Damped mode tries the full step first, then halves α until it achieves a sufficient decrease in the squared residual:

Accept a step only if the squared residual decreases by the required fraction.

The implementation tries α = 1, ½, ¼, and so on, down to 2⁻²⁰: 21 candidates. If no finite trial is accepted, it reports stagnation, or a nonfinite outcome if the final trial has invalid numerical values. Undamped mode tries only α = 1 and accepts it if its diagnostics are finite, even if its residual increases.

The stopping measurement is the root mean square residual, which divides out the number of coordinate equations:

RMS is the residual vector length divided by the square root of 2N.

The default convergence threshold is 0.0000001 (10⁻⁷), with at most 100 Newton iterations. Each initial guess is solved independently and has its own status:

Running
More iterations may be attempted.
Converged
The RMS residual is at or below the requested tolerance.
Stagnated
Backtracking could not find an acceptable step.
Singular
The linear solver could not solve the Jacobian system.
Nonfinite
An invalid or infinite numerical value prevented a usable step.
Iteration limit
The iteration budget was exhausted before convergence.

A rejected or failed update keeps the last accepted path and diagnostics. An initially converged guess needs no iterations. Convergence on the final allowed iteration counts as convergence.

13 / A SMALL WORKED EXAMPLE

One point, one Newton step.

Take uniform cost c = 1, start at (0, 0), end at (4, 0), and use just one interior point. Guess that the middle point is (2, 1). There are two intervals, so h = ½.

The cost gradient is zero, so F = 0. Only the finite-difference acceleration remains:

The guessed middle point gives residual (0, −8).

The Jacobian is −2I/h² = −8I. Newton's linear solve gives:

Solve −8IΔ = (0, 8), obtaining the move Δ = (0, −1).

The new midpoint is (2, 0). The path is straight, the residual is zero, and the full step is accepted. In a uniform field the equations are linear, so one Newton step is enough. Obstacles make F nonlinear, which is why repeated iterations become necessary.

14 / WHAT THE PLOTS MEAN

Small residual does not mean “best route.”

The solver finds a root of the discretized Euler–Lagrange equations. It does not directly minimize a discrete objective, and it does not prove that the root is a minimum. A symmetric path through a high-cost region can remain stationary. Different initial guesses can lead to different roots.

The displayed energy is a separate midpoint-quadrature estimate. Let mᵢ be the midpoint of a segment and dᵢ its displacement:

Displayed energy sums midpoint cost times squared segment displacement divided by h.

The displayed length is simply the sum of segment lengths. It is unweighted geometric length, not the intended cost-weighted distance.

Geometric length and a midpoint estimate of weighted distance use different segment weights.

The latter expression shows how to estimate the intended weighted-distance objective; it is not currently a playground diagnostic. A corrected energy diagnostic would instead square c(mᵢ) in the energy sum.

  • Residual and energy need not fall together. Backtracking controls residual. The midpoint energy is not the exact discrete functional whose gradient the solver sets to zero.
  • A finer grid is an accuracy check. A coarse grid may miss a narrow obstacle even with a tiny residual. Compare paths after increasing N.
  • The two solver modes solve the same current ODE. Damping changes the iteration strategy, not the objective.
  • Rover playback is geometric. It follows the displayed polyline at constant ordinary speed; it does not use the ODE's selected parameter speed or simulate vehicle dynamics.

15 / CONNECT THE MATH TO THE PROJECT

Where each piece lives.

The numerical source is src/path_planning_ode/core.py. These names connect it to the derivation:

Code Role
_field Gaussian cost, gradient, and Hessian.
_ode_derivatives The current F, Fq, and Fv, using A = c.
initialize Sample one of the three polynomial guesses.
residual / jacobian Assemble the finite-difference system and its derivatives.
step Perform a linear solve, backtracking if enabled, and update the path.
solve Repeat independently for each guess and record the iteration history.
energy / _state Calculate diagnostics and determine stopping status.

The numerical tests independently construct the current Euler–Lagrange equations with SymPy, compare the analytic Jacobian against numerical differentiation, and check straight-line recovery, symmetry, refinement, and failure handling. They establish consistency with the current objective; they do not certify that it is the intended objective.

In the browser, a worker runs this same Python package through Pyodide. It sends path snapshots to the interface one iteration at a time. Rendering and interaction run separately from the solver.
